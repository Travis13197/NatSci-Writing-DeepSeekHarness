# 生物学语义清晰度、术语落地与整篇阅读审计

版本 1.0.0；更新 2026-11-24。处理含蛋白、突变、模型分数、结构、数据集、实验测定或内部项目编号的中文全文、完整 HTML、图题和图注时完整阅读。本文件由 BioNoether 1.2.6.1 回归归纳，原因是技术审计全部通过时，读者仍无法理解标题中的“局部操作变量”“1PGA 热点”“Olson 端点增量”和“空间语法”。

## 1. 通过标准

一位没有参加项目的结构生物学或蛋白质工程研究者，在不看代码、不参加讨论的情况下，应能回答：

1. 研究的是哪个蛋白、哪个模型、哪些突变和哪些测量？
2. 模型具体计算了什么，输出量是什么，正负号表示什么？
3. 在哪个数据集、多少样本和哪些留出单位上评价？
4. 观察到的数值规律是什么，和哪个基线相比？
5. 结构图中的颜色、透明度、Cartoon、侧链和残基标签分别表示什么？
6. 这个结果支持什么，不支持什么？

任何一项需要读者猜测，就未通过。

## 2. 强制句子骨架

标题、摘要首句和图级结论使用同一骨架：

> 在【蛋白/体系】中，【模型】对【突变类型】的响应形成【可测量的位点或空间规律】；与【基线】相比，它在【数据集/测定】的【留出单位】上改变【效应量与区间】；该结果只支持【范围】，不支持【越界解释】。

例：

> 在 GB1 中，ESMC-6B 对 1,045 个单氨基酸替换的响应在构造位置 258–266 形成峰值；这些位点映射到 PDB 1PGA 后形成局部残基区域；把候选评分加入化学和结构基线后，1,026 个 Olson GB1–IgG 结合数据的留出 R² 中位提高 0.0979。

不要把句子写成：

> GB1 局部操作变量映射到 1PGA 热点并保留 Olson 端点增量。

后者没有说明变量、热点、端点、增量和“保留”分别是什么。

## 3. 首次定义

每个缩写和项目名称第一次出现时写成“全名（缩写）”。数据集名称之后立刻写实验对象和测定。

| 类型 | 必须写清 |
|---|---|
| 蛋白 | 全名、结构域、物种或构建体；PDB 编号对应哪一项结构 |
| 模型 | 模型名、冻结状态、读出的层/池化方式 |
| 分数 | 输入、计算单位、候选方向、正负号含义、聚合方式 |
| 数据集 | 原始研究、实验对象、测定、分数类型、匹配后的样本数 |
| 结构 | 实验结构、预测结构或登记拓扑；非重点与重点表示 |
| 统计量 | 留出单位、基线、中心、区间、置换或校正方法 |
| 因果/能量 | 只有直接测量支持时才能使用；否则写关联、预测、候选 |

例：`1PGA` 不能只作为编号出现；第一次写“GB1 的实验结构（PDB 1PGA）”。`Olson` 不能单独充当端点；第一次写“Olson 等 2014 年测得的 GB1–IgG 结合数据”。`quadratic-8` 要写“由八项二次项组成的候选评分”。

## 4. 受控词表

默认删除或改写：

- `面板`、`increment panel`、`增量面板` → `图 1a`、`子图 a`、直接陈述；
- `局部操作变量` → `位点响应评分`，随后定义原始分数与位点聚合；
- `操作方向` → `候选分数方向（正负号仅定义评分方向）`；
- `操作图` → `单突变集合`、`突变邻域` 或具体替换数据；
- `身份匹配` → `氨基酸身份逐位核对后的序列—结构对应`；
- `空间语法` → `相同的序列—结构显示与残基编号规则`；
- `证据层`、`证据维度` → `证据类型`、`独立验证`；
- `可检测的信息` → 具体写 `在 20/20 次留出中提高 R²` 或 `未达到检测下限`；
- `保留增量` → `加入 A 后 R² 增加 ΔR²=...`；
- `通过门/门控` → `达到预设判据`、`满足预设条件`；
- `研究卡/路线` → `研究问题`、`比较方案`；
- `模型世界` → 具体写模型、数据和评价范围；
- `within/between`、`coverage@0.2`、`no-refit` → 第一次出现时写中文全称与数字定义。

科学上精确的 `burial`、`B-factor`、`RMSF`、`Rg` 等可以保留，但第一次出现要写中文解释。内部任务号 W0、H3、RC03 只用于索引，正文以科学名称叙述。

## 5. 分数、方向和端点

- 模型分数不是效应方向。若正负号由候选向量的符号规范决定，写“正负号只区分候选方向，不表示提高或降低”。
- 位点内离散必须说明对象：`同一位点不同替换之间的标准差`。不要把 RMS 当作围绕均值的标准差；若已有 `E[q²]` 和 `E[q]`，标准差由 `sqrt(E[q²] − E[q]²)` 计算，并保留非负下限。
- 数据集的 DMS score、结合选择、稳定性、活性或自由能是不同量。只写数据实际测量的对象。
- 留出 R² 提高量写作 `ΔR² = R²(基线 + 候选) − R²(基线)`，并写重复次数、分组单位和区间。

## 6. 图题与图注

- 标题是完整生物学关系，不是内部变量名拼接。
- 逐子图说明使用 `a，…… b，……`，不使用 `面板。`
- 结构子图要写清是完整结构、局部视图还是两种状态比较。主结果每个子图只显示一个完整蛋白。
- 结构颜色说明必须明确：非重点区域浅灰半透明；关键残基不透明 Cartoon；侧链 sticks；残基标签直接给出范围。
- 图注中写 `Q32–Y33` 时，前后要说明这是单字母氨基酸代码和 PDB 残基编号。

推荐图注结构：

> **图 1 | 模型响应在 GB1 序列和 1PGA 结构中形成局部区域，并提高结合数据的留出预测。** a，每个构造位点的平均候选分数和同一位点不同替换之间的标准差。b，…… 统计：…… 颜色：…… 结构：…… 源数据：……

## 7. 结构图强制规则

1. 主结果结构子图只显示一个完整蛋白，除非合同明确比较两个构象或两个结构实体。
2. 禁止把完整结构和局部小图拼进同一个方形结果子图，造成“一大一小两个结构”。
3. 非重点蛋白区域使用中性浅灰并设置约 60–75% 透明度；关键残基 Cartoon 恢复为 0% 透明并保持琥珀色或其他固定语义色。
4. 关键残基同时显示 side-chain sticks；仅高亮 Cartoon 不足以显示氨基酸身份。
5. 直接标签默认 Arial 10.5 pt，比 11.5 pt 结构标题小 1 pt。标签写单残基 `A86` 或连续范围 `A86–E88`，放在对应高亮区域附近。
6. 标签范围必须来自真实 PDB 残基编号，不能使用构造编号替代；构造号与 PDB 号在源表和图注中同时保留。
7. 同一结构只显示一次；结构增强页用 Cartoon/Cylinder 控件切换表示，不复制多个大小不同的同一蛋白。

## 8. 整篇 HTML 审计

1. 按顺序导出所有可见标题、段落、列表、表格、图题、图注、按钮、交互提示和脚注。
2. 检索并逐条读上下文：`面板`、`局部操作变量`、`操作方向`、`操作图`、`身份匹配`、`空间语法`、`证据层`、`证据维度`、`可检测`、`通过门`、`研究卡`、`模型世界`、`no-refit`、`within/between`、`coverage@`。
3. 按首次出现位置核对每个缩写、蛋白、结构、数据集和评分。
4. 对每幅图的每个子图回答：显示什么、比较什么、n 是什么、颜色是什么、结构位置是什么、结论止于哪里。
5. 对结构子图核对蛋白个数、透明度、Cartoon、side-chain sticks、Arial 标签、字号和残基编号。
6. 运行完整浏览器检查，但文字可读性以可见文字审计为主，不以图片加载成功替代。

## 9. BioNoether 回归记录

- 旧标题 `GB1 局部操作变量映射到 1PGA 热点并保留 Olson 端点增量` 同时缺少变量定义、1PGA 蛋白身份、Olson 测定和增量定义。
- 旧句 `模型响应具有可重复的位点顺序，并能映射到局部结构热点；同一候选还携带 Olson 端点可检测的预测信息` 把统计结论、结构定位和实验预测压成内部缩写。
- 旧句 `身份匹配为七个蛋白提供了共同的空间语法` 没有说清按什么身份匹配、哪些蛋白、共同的是什么显示规则还是生物学规律。
- 图 1a 把 `q_rms` 当作围绕均值的离散度，但代码定义为 `sqrt(mean(q²))`；正确改法是使用位点内标准差。
- 结构渲染器主动把 whole view 与 focus view 拼入同一图，导致每个结构子图出现一大一小两个蛋白。主结果改为单一 whole view。
- 既往几何与哈希审计仍可能通过，因为这些检查没有“句子是否可理解”和“结构子图是否只有一个分子对象”的门。两个门现在都是发布条件。
